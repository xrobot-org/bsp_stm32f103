# bsp_stm32f103

STM32F103RCTx 的 LibXR / XRobot BSP / LibXR and XRobot BSP for the STM32F103RCTx

## 1. 板子与平台 / Board and Platform

芯片为 STM32F103RCTx（BluePill 工程名），系统为 FreeRTOS，终端通过 USB CDC（`usb_fs_cdc`）提供。外设由 CubeMX 工程 `STM32F103RC.ioc` 配置，`libxr` 命令生成入口源文件 `User/app_main.cpp`，并在其中用 `XR_REGISTER` 完成硬件注册。配置中的硬件名即这些注册名：`LED`、`PA8`、`pwm_tim2_ch3`、`adc1_adc_channel_0`、`spi1`、`usart1`、`i2c1`、`usb_fs_cdc`、`ramfs`、`terminal`、`power_manager`。

```text
STM32F103RC.ioc           CubeMX 工程
Core/ Drivers/            CubeMX 生成的初始化代码与 ST HAL / CMSIS
Middlewares/              FreeRTOS、ST USB Device 库、LibXR 子模块
Modules/modules.yaml      使用的模块（`xrobot:` 记录 XRobot 版本）
Modules/sources.yaml      源
xrobot.lock               每个模块使用的提交（lock）
User/app_main.cpp         入口源文件，硬件注册并调用 XROBOT_MAIN()
User/libxr_config.yaml    LibXR 外设参数（`generator:` 记录 CodeGenerator 版本）
User/xrobot.yaml          配置
```

`Modules/<owner>/<Repo>/`、`Modules/CMakeLists.txt` 和 `User/xrobot_main.hpp` 由 `xrobot` 生成，已列入 `.gitignore`。

The chip is the STM32F103RCTx (project name BluePill). The system is FreeRTOS and the terminal is provided over USB CDC (`usb_fs_cdc`). The peripherals are configured in the CubeMX project `STM32F103RC.ioc`; the `libxr` command generates the entry source `User/app_main.cpp`, which performs the hardware registration with `XR_REGISTER`. The hardware names used in a configuration are these registered names: `LED`, `PA8`, `pwm_tim2_ch3`, `adc1_adc_channel_0`, `spi1`, `usart1`, `i2c1`, `usb_fs_cdc`, `ramfs`, `terminal` and `power_manager`.

`Modules/<owner>/<Repo>/`, `Modules/CMakeLists.txt` and `User/xrobot_main.hpp` are generated by `xrobot` and listed in `.gitignore`.

## 3. 构建 / Build

构建使用 CMake、Ninja 和 ST 的 `starm-clang` 工具链（STM32CubeCLT 或 VS Code STM32Cube 扩展提供），`starm-clang` 位于 `PATH` 中。预设使用 `cmake/starm-clang.cmake`（picolibc 配置）。XRobot 为 1.0.0，LibXR CodeGenerator 为 6.0.0，与 `Modules/modules.yaml` 的 `xrobot:` 和 `User/libxr_config.yaml` 的 `generator:` 一致。

```bash
git clone --recursive https://github.com/xrobot-org/bsp_stm32f103.git
cd bsp_stm32f103
pip install xrobot==1.0.0 libxr==6.0.0
xrobot setup
cmake --preset debug
cmake --build --preset debug
```

`xrobot setup` 拉取模块、检查配置并生成 `User/xrobot_main.hpp`。CMake 预设为 `debug`、`relWithDebInfo`、`release` 和 `minSizeRel`，产物为 `build/<预设>/BluePill.elf`。构建时 LibXR 检查配置、lock、模块头文件和入口源文件中的硬件注册相对 `User/xrobot_main.hpp` 是否有变化，有变化时构建失败并提示对应的 `xrobot gen -c <配置>`。

在 CubeMX 中修改并重新生成代码后，运行 `libxr stm32 setup` 更新 `User/app_main.cpp`、`User/app_main.h`、`User/flash_map.hpp`、`User/libxr_config.yaml` 和 `cmake/LibXR.CMake`，`User Code` 区域保留。命令说明见 [LibXR_CppCodeGenerator](https://github.com/xrobot-org/LibXR_CppCodeGenerator)。

`.github/workflows/xrobot_stm32.yml` 在 `ghcr.io/xrobot-org/docker-image-stm32:main` 中安装固定版本的工具，用 `libxr parse` 和 `libxr gen` 重新生成上述文件并与提交比对，运行 `xrobot format --check` 和 `xrobot setup --frozen`，再构建固件。`dev` 分支接收修改，`master` 分支由 `dev` 的 PR 更新。

Building uses CMake, Ninja and ST's `starm-clang` toolchain (provided by STM32CubeCLT or the VS Code STM32Cube extension), with `starm-clang` on `PATH`. The presets use `cmake/starm-clang.cmake` (picolibc configuration). XRobot is 1.0.0 and the LibXR CodeGenerator is 6.0.0, matching `xrobot:` in `Modules/modules.yaml` and `generator:` in `User/libxr_config.yaml`.

`xrobot setup` fetches the Modules, checks the configurations and generates `User/xrobot_main.hpp`. The CMake presets are `debug`, `relWithDebInfo`, `release` and `minSizeRel`, and the output is `build/<preset>/BluePill.elf`. During the build, LibXR checks whether the configurations, the lock, the Module headers and the hardware registrations in the entry source changed relative to `User/xrobot_main.hpp`; on a change the build fails and names the matching `xrobot gen -c <configuration>`.

After changing and regenerating the code in CubeMX, `libxr stm32 setup` updates `User/app_main.cpp`, `User/app_main.h`, `User/flash_map.hpp`, `User/libxr_config.yaml` and `cmake/LibXR.CMake`, and keeps the `User Code` regions. The commands are described in [LibXR_CppCodeGenerator](https://github.com/xrobot-org/LibXR_CppCodeGenerator).

`.github/workflows/xrobot_stm32.yml` installs the pinned tools in `ghcr.io/xrobot-org/docker-image-stm32:main`, regenerates the files above with `libxr parse` and `libxr gen` and compares them with the commit, runs `xrobot format --check` and `xrobot setup --frozen`, and then builds the firmware. The `dev` branch receives changes and the `master` branch is updated by PRs from `dev`.

## 4. 烧录与运行 / Flash and Run

`.vscode/tasks.json` 提供 VS Code 任务：`CubeProg: Flash project (SWD)` 用 STM32CubeProgrammer 命令行通过 SWD 下载当前 CMake 目标并复位运行，`Build + Flash` 先重新构建再下载，`CubeProg: List all available communication interfaces` 列出调试器。对应的命令为：

```bash
STM32_Programmer_CLI --connect port=swd --download build/debug/BluePill.elf -hardRst -rst --start
```

运行后通过 USB CDC 连接终端。

`.vscode/tasks.json` provides VS Code tasks: `CubeProg: Flash project (SWD)` downloads the current CMake target over SWD with the STM32CubeProgrammer command line and resets the chip to run it, `Build + Flash` rebuilds first and then downloads, and `CubeProg: List all available communication interfaces` lists the debug probes. The corresponding command is the one shown above. At run time the terminal is available over USB CDC.
